# Beginner glossary

| Word | Meaning |
| --- | --- |
| File / folder / path | Saved item / container / its location |
| Current folder | Where relative commands act |
| Terminal / shell | Command window / program interpreting commands |
| Command / output | Instruction you type / its result |
| WSL / Ubuntu | Linux inside Windows / the Linux distribution used here |
| VS Code / extension | Editor / optional editor add-on |
| HTML / CSS | Page content/structure / appearance/layout |
| Repository (repo) | Project files plus version history |
| Git / GitHub | Local history tool / online repository platform |
| Source Control in VS Code | A UI for Git; operates on the same repository as Git CLI |
| Working tree | Your checked-out project files |
| Diff | Comparison showing changed lines |
| Stage | Select changes for the next commit |
| Commit | Recorded checkpoint with message and ID |
| Branch | Line of development; workshop uses main |
| Fork / clone | Your online copy / checkout on your computer |
| Remote / origin | Online repository URL / common local nickname |
| Fetch | Download remote history without changing your working branch |
| Push / pull | Send commits / fetch and integrate remote commits |
| Authentication / token | Prove write access / secret credential |
| Actions / Pages | Runs workflows / hosts your static portfolio |
| Deployment / public URL | Publish files / address other people can open |

**Edit → save → preview → stage → commit → push → deployment.** Saving writes the local file. Committing records local history. Pushing shares history. Deployment publishes the page afterward.
